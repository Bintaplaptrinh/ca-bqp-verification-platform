## Real bugs found and fixed this session (not hypothetical, each confirmed via a live run before and after)

1. A fully fabricated client-side fallback in `CABQPVerification.jsx`'s search handler silently produced fake BCA/BQP/OTHER verdicts (regex-guessed from department/position keywords) with hardcoded scores whenever the real backend call didn't yield a usable case_id — indistinguishable from a real result, never labeled synthetic. Removed; replaced with a proper error state.
2. `HistoryView`'s "Xem lại" replayed a locally-cached row with `subject_group`/`eligibility`/`salary_status` hardcoded to placeholder values instead of re-fetching. Fixed to call `GET /cases/{id}` for real.
3. Both "Xem hồ sơ gốc" and "Đối chiếu chi tiết" modals fabricated decision numbers, signer titles, a toy checksum, fake CCCD numbers, and fake match percentages. Rewritten to show only real fields from `GET /cases/{id}`; the fake "Phê duyệt đối soát" approval button (no backend endpoint ever backed it) was removed.
4. `ReviewsPage.jsx` had no self-assign/release/reassign UI, no optimistic-lock conflict handling, and displayed every review's `case_id` as the literal string `CASE_XXX` regardless of the real id (a slice-before-strip bug). Both fixed; verified live with a real two-tab 409 conflict.
5. `ReviewsPage.jsx` fetched a fixed 100 items with no pagination against a `GET /reviews` endpoint that sorts oldest-first — in the shared dev database (170+ real OPEN reviews), newly created reviews were completely unreachable through the UI. Added real page/total controls.
